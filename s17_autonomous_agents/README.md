# 第 17 课：Autonomous Agents — 自己看板，自己认领

## 核心概念：为什么需要自治？

在 s16 中，虽然队友有了体面的关机和审批协议，但老大的工作依然很累：**必须手动把任务派发给指定的队友**。
如果任务看板上有 10 个未认领的任务，老大就得手动分配 10 次。

在一个成熟的敏捷团队里，员工（队友）应该是**自组织的 (Autonomous)**：
1. 老大只负责写黑板（创建任务列表）。
2. 队友干完手头的活，不应该傻站着等分配，而是自己去看黑板（扫任务列表）。
3. 发现没人认领的任务，就自己接单（Claim Task），干完再找下一个。
4. 如果连续 1 分钟都没新活干，队友就自动打卡下班（退出线程），绝不浪费资源。

## 核心改造：如何让队友变聪明？

在 s17 中，我们让队友的生命周期发生了质的飞跃。

### 1. 三阶段生命周期
之前的队友只有“干活”和“死掉”两个状态。现在的队友有三个阶段：
- **WORK（干活）**：调用工具写代码，最多思考 10 轮。
- **IDLE（摸鱼/轮询）**：干完活了不退出。每隔 5 秒去扫一眼**邮箱 (Inbox)**和**任务看板 (Task Board)**。
- **SHUTDOWN（下班）**：如果连续 60 秒（轮询 12 次）都没收到新任务，或者老大发来了关机请求，就自动总结汇报并结束线程。

### 2. 空闲轮询 (idle_poll)
当队友进入 IDLE 阶段时，它会执行以下逻辑：
```python
# 1. 查邮箱：有没有老大发来的私信？（尤其是关机请求，立刻响应）
# 2. 看黑板：有没有状态是 pending，并且依赖任务已经做完的任务？
# 3. 抢单：调用 claim_task，如果抢单成功，回到 WORK 阶段干活。
```

### 3. 依赖解锁与防抢单 (Claim 检查)
在扫描看板时，不仅要找没人做的任务，还要检查 `blockedBy`（前置依赖）是不是都做完了（`can_start` 函数）。
并且在 `claim_task` 时，会检查这个任务是不是已经被别人抢走了（检查 `owner` 字段），防止两个队友同时做一个任务。

### 第 2 步：体验“全自动敏捷开发团队”
向 Agent（老大）发送如下指令：
> `请创建 3 个互相独立的任务，然后召唤两个队友 alice 和 bob。接下来你什么都不用做，就看着他们自己认领任务干活。`

**观察极度舒适的自动化协作：**
1. 老大会调用 3 次 `create_task`，然后调用 2 次 `spawn_teammate`，接着它就进入空闲状态喝茶去了。
2. alice 和 bob 启动后，会立刻进入 IDLE 轮询。
3. 突然，alice 扫描到了任务 1，终端打印 `[Team] alice 认领了任务...`
4. bob 扫描到了任务 2，终端打印 `[Team] bob 认领了任务...`
5. 他们并行干活，干完后自动标记为 `complete`。
6. alice 干完后又去轮询，发现还有任务 3，继续认领。
7. 等所有任务做完，他们轮询了 60 秒发现实在没活干了，就会打印 `[Team] 队友 alice 体面退出`。
