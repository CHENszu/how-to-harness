# 第十二课：Task System —— 把大目标拆成小任务

## 核心概念：为什么需要任务系统？

在第 5 节（s05_todo_write）中，我们教 Agent 使用 `TodoWrite` 工具列任务清单。但这只是“记事本”级别，适合单个 Agent 执行短周期的简单任务。
在真实的复杂项目中，你会遇到这样的场景：
1. **依赖关系**：有些任务必须先完成（比如先搭建数据库，才能写 API）。
2. **多终端/多 Agent 协作**：任务如果只存在内存里，程序一重启或者换个 Agent 就没了，大家没法协同工作。
3. **长期追踪**：一个大型重构可能需要几天时间，需要像 Jira 一样管理任务状态。

所以，我们需要将 `TodoWrite` 升级为真正的 **Task System (任务系统)**：每个任务都是硬盘上的一个 JSON 文件，任务之间有阻塞（`blockedBy`）依赖关系，任务状态可以通过状态机（Pending -> In Progress -> Completed）进行管理。

**Harness 层的核心设计：持久化文件 + 依赖图 (DAG) + 状态流转。**

## 核心改造：基于文件的任务管理器

在 s12 中，为了专注讲解任务系统，我们去掉了 s11 的外层错误恢复逻辑。我们引入了一个 `.tasks/` 目录和 5 个全新的工具：

### 1. 任务数据结构 (`Task`)
每个任务现在长这样：
```json
{
  "id": "task_1700000000_1234",
  "subject": "设计数据库表结构",
  "description": "需要 User 和 Post 两个表",
  "status": "pending",
  "owner": null,
  "blockedBy": []
}
```

### 2. 依赖检查 (`can_start`)
任务能否开始，取决于它的 `blockedBy`（前置依赖）是否全部变为了 `completed` 状态。如果某个依赖任务没完成，当前任务就被死死卡住（Blocked）。

### 3. 五个新的任务控制工具
我们给 Agent 配备了以下“Jira 管理员”工具：
- `create_task`: 创建任务，并可以指定 `blockedBy` 依赖。
- `list_tasks`: 查看当前所有任务及状态。
- `get_task`: 查看某个任务的详细描述。
- `claim_task`: **认领任务**。把状态从 `pending` 变为 `in_progress`，并在 `owner` 字段写上自己的名字。如果前置依赖没做完，认领会被拒绝。
- `complete_task`: **完成任务**。把状态改为 `completed`，并自动扫描是否有下游任务因为当前任务的完成而被“解锁（Unblocked）”。

## 实践操作指南

我已经为你适配并准备好了带中文注释的可运行代码。

### 第 1 步：运行 s12
在终端中运行：
```bash
python s12_task_system/code_annotated.py
```

### 第 2 步：体验创建任务流
你可以直接对 Agent 说：
> `请帮我创建一个关于开发博客系统的任务流。首先需要“设计数据库表结构”，然后“开发API接口”（依赖数据库），最后“编写接口文档”（依赖API）。创建完毕后，帮我列出所有任务的状态。`

**观察重点：**
1. 观察项目根目录下是否多出了一个 `.tasks/` 文件夹，里面是否存有 JSON 格式的任务文件。
2. 接着对 Agent 说：`帮我认领并完成第一个任务，看看有什么任务被解锁了？`
3. 观察终端输出的绿色日志 `[complete] 设计数据库表结构 ✓` 以及黄色日志 `[unblocked] 开发API接口`。

通过这个任务系统，我们的单体 Agent 已经具备了“项目经理”的能力。它不再是一头乱撞的苍蝇，而是能有条理、分先后地啃下硬骨头。这也为将来**多个 Agent 同时认领任务、协同干活**打下了最坚实的地基！
