# 第11模块：Plugin 插件机制 (生态兼容)

## 1. 核心理念：“站在巨人的肩膀上”
如果说前面的 `Tool`（工具）、`Skill`（技能）和 `Hook`（钩子）是我们在本地自己一点点搭建的“积木”，那么 `Plugin`（插件模块）的核心目的就是——**直接把别人搭好的高级积木搬过来用**。

OpenHarness 在设计上刻意保持了与官方 Claude 客户端（如 Claude Desktop 和 Claude Code）的高度一致。它相当于一个“第三方改装车头”，能够完美适配官方原厂的各种“货箱”。

## 2. 直观比喻：改装车头与原厂货箱
结合我们之前的理解，整个生态兼容机制可以这样类比：
* **第三方改装车头（OpenHarness）**：我们自己编写的 Agent 引擎。
* **原厂定制货箱（Skills / MCP 服务器）**：在官方 Claude 生态中配置好的 Markdown 技能和各种外部工具连接器。
* **高速 ETC 卡（凭证共享）**：官方的登录 Token（如 `~/.claude/.credentials.json`）。

当我们把车头造好，只要挂钩（Plugin Loader）标准一致，我们就能直接挂上原厂货箱、插上 ETC，一脚油门上高速，而不需要重新造货箱或重新办卡。

## 3. 插件模块的四大核心能力

### 3.1 原生支持 MCP (Model Context Protocol)
MCP 是大模型与外部工具通信的标准协议。
* OpenHarness 内部包含一个完整的 MCP 客户端管理器。
* **作用**：可以直接对接现有的 MCP 服务器（比如别人写好的连接数据库、读取本地文件的服务器），并通过 `mcp_tool.py` 将它们动态转化为我们的 Agent 可以直接调用的本地工具。

### 3.2 Claude 技能（Skill）零成本复用
* 官方 Claude Code 允许在 `.claude/skills` 下编写 `SKILL.md`。
* **作用**：OpenHarness 的插件加载器会自动扫描并解析这些官方格式的目录和文件，直接将其纳为己用。不用重新手写 Prompt，直接复用。

### 3.3 配置文件与生命周期兼容
* 识别 `.claude-plugin/plugin.json` 等标准 Manifest。
* 支持 `hooks.json`，让外部插件也能介入我们上一节写的 `10_hook` 生命周期（如在执行命令前后自动触发）。
* 支持特有的环境变量占位符（如 `${CLAUDE_PLUGIN_ROOT}`）。

### 3.4 登录凭证与环境共享
* **作用**：直接读取本地系统中的官方 Claude 登录凭据（通过 `external.py`）。Agent 运行时自动携带合法的 `User-Agent` 和计费 Header 发起请求，实现真正的“白嫖”登录状态。

## 4. 总结与后续代码实现思路
**“慢就是快”**：理解 Plugin 的本质，并不是要写多么复杂的底层 AI 逻辑，而是要写各种 **“适配器（Adapter）”和“加载器（Loader）”**。

在接下来的代码实现中，我们的核心任务将会是：
1. **写一个 Loader**：去固定路径“进货”（扫描 `.claude/` 下的配置文件和技能）。
2. **写一个 Adapter**：把 MCP 协议传过来的能力翻译成我们的 `BaseTool` 格式。
3. **完成装配**：把加载到的外部资源注册到我们的 `Engine` 中。

*(注：本节仅作原理总结，为保持进度节奏，具体代码实现将在后续需要时再展开。)*
