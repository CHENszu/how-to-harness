# 第0节：从提示词到 Harness —— 大模型工程的演进历程

在学习如何构建 Harness（脚手架/运行框架）之前，我们需要先理解大模型应用开发是如何一步步演进到今天的。
主张“慢就是快”，我们先通过直观的比喻，深度理解这三个核心阶段的本质区别。

## 1. 提示词工程 (Prompt Engineering)

**阶段本质**：教大模型“如何思考”。

**直观比喻**：**“写一封完美的指令信”** 或 **“闭卷考试”**。
在最初阶段，我们把大模型看作一个极度聪明但没有记忆和外部连接的大脑。所有的优化都集中在“如何把话说明白”。
比如通过 Zero-shot、Few-shot（给几个例子）、CoT（思维链，让它一步步想）等技巧，试图仅靠一段完美的文本提示，让模型在闭卷考试中拿高分。

**局限性**：再好的指令，也无法让模型知道它训练数据之外的事情（比如你昨天的订单记录），或者执行具体动作（比如帮你发邮件）。

## 2. 上下文工程 (Context Engineering)

**阶段本质**：给大模型“喂数据”。

**直观比喻**：**“开卷考试”** 或 **“给新员工配齐档案袋”**。
为了解决模型不知道外部知识的问题，我们进入了上下文工程阶段（RAG 检索增强生成就是最典型的代表）。
我们不再只纠结于提示词的语气，而是建立了一套检索系统：当用户提问时，先去数据库里把相关的知识（比如公司规定、历史文档）搜出来，打包塞进提示词里（上下文），然后再让模型回答。

**局限性**：模型此时变成了一个“博学的客服”，但它依然是个被动的文字生成器。它能告诉你衣服该怎么洗，但没法帮你把衣服放进洗衣机并按下启动键。

## 3. Harness 工程 (Harness Engineering)

**阶段本质**：为大模型“造整车”。

**直观比喻**：**“汽车流水线”** 或 **“为发动机配备方向盘和底盘”**。
大模型本身只是一个强大的“发动机”（负责推理和决策）。要让它真正在现实世界跑起来，我们需要为它建造一辆完整的汽车——这就是 Harness（运行框架/脚手架）。

在 Harness 工程中，我们关注的不再仅仅是文本，而是**系统架构**：
- **方向盘和四肢（工具调用/Tool Use）**：赋予模型执行动作的能力（读写文件、发网络请求、执行代码）。
- **仪表盘和行车记录仪（记忆系统/Memory）**：让模型能记住跨越多次对话的上下文，甚至总结长期经验。
- **变速箱（Agent Loop/Hooks）**：让模型能自主循环思考、执行、观察结果，并在关键节点进行拦截和权限校验。
- **车载电脑（后台任务与调度/Cron & Background）**：让模型在空闲时也能自主处理异步任务（就像“洗衣服”这个后台任务），而不是永远被动等待用户输入。
- **车队协同（多智能体/Multi-Agent）**：让不同的“汽车”（Agent）通过消息总线互相通信，协同完成复杂项目。

**总结**：
- 提示词工程：研究如何更好地与发动机对话。
- 上下文工程：给发动机提供更高质量的燃料（知识）。
- **Harness 工程：围绕发动机，打造一台能够自主感知、决策并执行的全自动驾驶汽车。**

本系列教程（how-to-harness）正是带你从零开始，通过代码手写这台“汽车”的每一个零部件，深度理解大模型 Agent 底层运行的真正原理。

## 4. 学习路径与目录结构

本项目包含两条学习主线：

- **外层目录 (01-20)**：参照 `shareAI-lab/learn-claude-code` 构建的高阶应用，较为复杂，适合作为最终目标参考。
- **内层目录 (`s00_evolution/`)**：这是我们的**核心学习沙箱**！我们将 `HKUDS/OpenHarness` 的源码拆解成了 10 个进阶模块，带你“造轮子”式地从零手搓一个完整的 Agent 引擎：
  - `01_agent_loop`：实现基础的反应式循环 (While True + Tool Calls)
  - `02_tools`：接入网络搜索和本地命令执行能力
  - `03_web_search` / `04_web_fetch`：强化网络信息获取
  - `05_sandbox`：实现隔离的代码执行环境
  - `06_short_term_memory`：实现四级递进的上下文压缩策略
  - `07_long_term_memory`：实现跨会话的记忆持久化
  - `08_permission_control`：实现三级权限管控 (DEFAULT, PLAN, FULL_AUTO) 与审批挂起
  - `09_skill`：实现“渐进式披露”的 Skill 按需加载与知识挂载机制

> 建议：按照 `s00_evolution` 目录的序号顺序学习，感受 Agent 框架是如何一步步从简陋走向完善的。
