# 10. Hook 机制 (卡点质检系统)

## 🧐 什么是 Hook (钩子)？能干啥？

简单来说，**Hook 就是系统核心流程中预留的“插槽”或“工位”**。

在很多真实的商业 AI 产品中，大模型本身只负责解决业务问题，但产品往往需要满足各种外围的**合规、安全、计费、日志**要求。如果把这些要求全写进大模型的 Prompt 里，不仅极其浪费 Token，而且大模型常常会“幻觉”导致漏加。

**典型应用场景：**
1. **金融免责声明 (合规护栏)**：当识别到用户在问理财、股票问题时，不管大模型回答了什么，Hook 都会在最终输出的末尾强制拼接一句：“*本回答由AI生成，仅供参考，请仔细甄别，谨慎投资。*”（本节已实现测试！）
2. **危险操作拦截 (安全护栏)**：在 Agent 执行 `rm -rf` 等危险系统命令前，Hook 会拦截并拒绝执行。
3. **计费与监控 (业务旁路)**：在 Agent 结束思考时，Hook 负责统计本次对话消耗的 Token 并上报计费系统。

通过 Hook 机制，我们可以将核心逻辑（Agent 思考）与外围策略（合规/拦截）**完全解耦**。

---

## 🎯 本节目标
在全自动模式（`FULL_AUTO`）下，Agent 的执行速度极快，但也带来了安全隐患。为了在不修改核心循环（Agent Loop）的前提下，能够灵活地对 Agent 的行为进行**拦截、记录和验证**，我们引入了高度解耦的 **Hook (钩子) 机制**。

你可以把 Agent Loop 想象成一条**汽车生产流水线**，而 Hook 机制就是一套**高度可定制的“卡点质检系统”**。

---

## 🛠️ 核心架构拆解

本节我们对架构进行了清晰的模块化拆分，新增了 `hooks/` 目录：

### 1. 零件标准：事件与结构
- **`events.py`**: 定义了流水线上的关键工位。
  - `PRE_TOOL_USE`：机械臂装配零件前的“安检站”（工具执行前拦截）。
  - `POST_TOOL_USE`：零件装配完成后的“质检站”（观察工具输出）。
  - `BEFORE_REPLY`：最终将结果交付给用户前的“包装站”（可以修改大模型的最终回复，如追加免责声明）。
  - `STOP`：汽车下线出厂前的“最终核验站”（Agent 停机时）。
- **`schemas.py`**: 定义了“质检员”的类型。目前支持：
  - `CommandHookDefinition`: 运行一段 Shell 脚本（机械检测仪器）。
  - `PromptHookDefinition`: 调用大模型进行安全审查（老工程师肉眼巡查）。
  - `DisclaimerHookDefinition`: 金融合规质检员，自动判断并追加免责声明。

### 2. 质检排班：`loader.py`
`HookRegistry` 扮演排班表管理者：
- 按照事件类型（Event）将 Hook 分门别类存放。
- 支持 `priority` 字段，数字越大越先执行，保证核心安全规则优先触发。

### 3. 流水线主管：`executor.py`
`HookExecutor` 负责真正的调度：
- 当 Agent Loop 走到特定工位时，呼叫主管。
- 主管调动对应的质检员进行检查。
- 如果拥有“一票否决权”的质检员（配置了 `block_on_failure=True`）喊停，主管立刻**拉停流水线**，返回拦截信息。

### 4. 核心卡点：`engine.py` 接入与触发机制
这是解耦的核心，Hook 的触发机制是基于 **生命周期事件 (Lifecycle Events)** 的。**Hook 的调用不是大模型主动发起的，而是代码引擎（流水线）在特定节点强制触发的**。

**触发流程（以金融免责声明为例）：**
1. **主线工人（主Agent）干活**：大模型思考并生成了包含推荐股票的回复，暂存在变量中准备发送。
2. **流水线运行到安检门 (`BEFORE_REPLY` Hook)**：`engine.py` 强制暂停发送，并将用户的输入和即将发送的回复交给 `HookExecutor`。
3. **后台 AI 质检员（辅助 LLM）上岗**：`executor.py` 会在后台偷偷发起一次**独立的大模型请求**（Prompt 编程），要求大模型判断用户输入是否属于金融领域（要求严格输出 `YES` 或 `NO`）。
4. **路由与裁决**：
   - 如果辅助大模型输出 `YES`，代码立刻触发拦截，将免责声明强行拼接在主Agent回复的末尾。
   - 如果输出 `NO`，则什么都不做，直接放行。

通过这种“主LLM干活 + 辅助LLM做裁判”的双层架构，实现了极其智能且灵活的动态路由。

在 `engine.py` 主循环中无缝插入的卡点示例：
```python
# engine.py 拦截逻辑缩影
if hook_executor:
    pre_hooks = hook_executor.execute(HookEvent.PRE_TOOL_USE, {...})
    if pre_hooks.blocked:
        # 被拦截，直接把错误反馈给 LLM，跳过本次工具执行
        result = f"被 Hook 系统拦截: {pre_hooks.error}"
        continue 
```

## 🚀 运行与体验

我们在 `main.py` 和 `test_run.py` 中挂载了两个直观的 Hook：
1. **Prompt Hook (安全拦截)**: 挂载在 `PRE_TOOL_USE`，如果大模型判定指令包含删除文件（rm, del）等危险操作，直接拦截。
2. **Command Hook (日志记录)**: 挂载在 `STOP`，Agent 运行结束时，自动执行 echo 写入一条停机日志到 `hook_log.txt`。

### 运行方式
```bash
# 激活环境
conda activate harness

# 运行交互模式
python main.py

# 运行测试脚本（演示 Agent 尝试删除文件被拦截，随后“抖机灵”用其他命令绕过的有趣过程）
python test_run.py
```

### 💡 为什么需要 Hook？
Hook 的最大价值在于**极度解耦**。
当我们需要增加新的安全护栏、性能监控、飞书通知、成本计算时，**完全不需要修改 `engine.py` 的核心代码**。只需按照标准写一个新的 Hook 挂载上去，系统就会自动调用它。这就是成熟 Agent 框架必备的扩展能力。
