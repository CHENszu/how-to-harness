# 第九课：Memory —— 跨越对话的长期记忆术

## 核心概念：为什么我们需要长期记忆？

在 s08 课中，我们实现了“上下文压缩”。当对话太长时，大模型会把它总结成一段摘要，从而防止 API 上下文爆满。
但是，**压缩是有损的**。很多重要的细节会在压缩过程中丢失。
比如，你可能在第 2 轮对话时说过：“写代码时请使用 tab 缩进，不要用空格。” 到了第 50 轮触发压缩后，这句话可能被总结成了一句泛泛的：“用户对代码风格有偏好”。甚至当你关掉程序重新运行（开启一个新的 Session）时，这些信息会彻底丢失。

因为 LLM 本身是无状态的，它的全部“记忆”都来自于你传给它的 `messages` 列表。我们需要一层**不参与压缩、能够跨会话（跨 Session）持久化保留的存储机制**。

**Harness 层的核心设计：文件仓库 + 索引 + 按需加载。**

---

## 核心改造：Memory 记忆系统的四大组件

在 s09 中，我们为 Agent 添加了一个 `.memory/` 目录。它的工作原理和人类记笔记非常相似。

### 1. 存储 (Storage)：Markdown + YAML 格式
每一条记忆都被保存为一个单独的 Markdown 文件，头部带有 YAML 元数据（Frontmatter）。例如 `user-preference-tabs.md`：
```markdown
---
name: user-preference-tabs
description: 用户喜欢使用 tab 进行缩进
type: user
---

User prefers using tabs, not spaces, for indentation.
**Why:** 保持代码库一致性。
```
除了单独的文件，还会自动维护一个 `MEMORY.md` 索引文件，里面记录了所有记忆的名称和简介。

### 2. 注入索引 (System Index)
在每一次对话开始前，程序会读取 `MEMORY.md` 这个索引文件，把它拼接到 SYSTEM Prompt 中。
这样，大模型就像拿到了一本“目录”，知道自己手头有哪些背景知识，但又不用把所有书本的内容全背下来。

### 3. 按需加载 (On-demand Loading)
每次用户发来新的请求，程序会把用户最近说的话和 `MEMORY.md` 目录一起发给大模型做一次快速查询（Side-query）：“你看下用户现在聊的，需要参考哪几条记忆？”
如果大模型选出了相关的记忆（比如它判断现在要写代码，应该看看缩进偏好），程序就把那个具体的 `.md` 文件内容读取出来，偷偷塞进当前轮次的 `messages` 里。

### 4. 自动提取与整理 (Extract & Consolidate)
**提取：** 我们不能指望用户每次都主动说“请记住这个”。在每一次 Agent 干完活（准备停下来等用户输入时），程序会在后台偷偷看一眼刚刚这段对话：“里面有没有包含用户的新偏好、新设定的规则？”如果有，就自动存成新的记忆文件。
**整理 (Dream)：** 记忆文件越来越多怎么办？如果超过了 10 个文件，程序会触发一次“做梦整理（Consolidate）”，让大模型去重、合并矛盾的信息、淘汰过时的记忆，始终保持记忆库的精简。

## 实践操作指南

我已经为你适配并准备好了带中文注释的可运行代码。

### 第 1 步：运行 s09
在终端中运行：
```bash
python s09_memory/code_annotated.py
```

### 第 2 步：体验记忆的写入与跨会话加载
请分多轮在终端中输入以下指令，观察 Agent 的行为：

1. `我写代码有个习惯，喜欢用 4 个空格缩进，不喜欢用 tab，你记住一下。`
   *(观察 Agent 回复后，终端是否输出了 `[Memory: extracted X new memories]`)*
2. `退出程序 (输入 q)`
3. 重新运行 `python s09_memory/code_annotated.py`
4. `写一个简单的 python 冒泡排序，保存到 test_bubble.py`
   *(观察它是否能自动应用你上一次对话中提出的“空格缩进”要求，并且终端会打印加载了哪些 Memory)*

体验完让 Agent 拥有长久记忆之后，你的 Agent 已经变得非常贴心和聪明了！这正是当今顶级 AI 工具（如 Cursor、Claude Code）的核心护城河之一。
