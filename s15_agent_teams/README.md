# 第 15 课：Agent Teams —— 一个搞不定，组队来

## 核心概念：为什么要组建多智能体团队？

当我们要让 Agent 完成“重构整个后端”这样极其庞大和复杂的任务时，单兵作战是不现实的。
如果让一个 Agent 去改数据库、写 API、又写测试，它的“脑容量（上下文窗口）”很快就会被海量的细节塞满，导致它修了 API 就忘了数据库，顾此失彼。

在 s06 中，我们学过“召唤小弟（Subagent）”。但小弟是**“临时工”**：老大让它干个活，它干完汇报一句话就死掉了。
如果我们需要几个长期存在、能互相商量、分工合作的角色（比如一个后端开发，一个前端开发），我们就需要**Agent 团队 (Teams)**。

---

## 核心改造：如何实现团队协作？

在 s15 中，我们给 Harness 增加了以下三大核心机制：

### 1. 文件收件箱 (MessageBus)
在团队中，Agent 之间不再是直接调函数的同步等待，而是通过**异步的“文件邮箱”**通信。
我们创建了一个 `.mailboxes/` 目录，里面有 `lead.jsonl`（老大的邮箱），`alice.jsonl`（后端开发的邮箱）。
- **发消息**：就是往对方的 `.jsonl` 文件里追加一行 JSON 数据。
- **收消息**：就是读取自己的 `.jsonl` 文件，读完后把文件清空。

### 2. 召唤长工队友 (spawn_teammate)
老大（Lead Agent）可以使用 `spawn_teammate` 工具来雇佣一个队友。
与 s06 的临时小弟不同，队友被召唤后，会在一个**独立的后台线程**里一直跑。
队友拥有：
- 独立的系统提示词（比如：“你是 Alice，一个资深后端开发”）。
- 独立的记忆（上下文）。
- 简化的工具箱（`bash`, `read_file`, `write_file`, `send_message`）。
队友最多会跑 10 轮思考（防止死循环），跑完后会把最终结果通过邮箱发给老大。

### 3. 老大的邮箱自动注入
老大在每一轮空闲时，都会去看看自己的 `lead.jsonl` 邮箱里有没有队友发来的新消息。
如果有，Harness 会把这些消息打包成 `[Inbox] From alice: ...` 这样的格式，偷偷塞进老大的对话历史里。
老大看到后，就能知道队友的进度，并继续发号施令或向你（人类）汇报。

## 实践操作指南

我已经为你准备好了带有中文注释的 `code_annotated.py`。
*(请放心，所有的 `run_bash` 依然带着防 GBK 乱码的护身符，大模型的调用格式也依然是完美兼容 DeepSeek 的 OpenAI 格式，容错机制也都在！)*

### 第 1 步：运行 s15
在终端中运行：
```bash
python s15_agent_teams/code_annotated.py
```

### 第 2 步：体验当包工头的感觉
请向 Agent（老大）发送如下指令：
> `请召唤一个名为 alice 的后端开发队友，让她创建一个 schema.sql 文件，里面写一张 users 表。`

**观察重点：**
1. **召唤队友**：老大很快会调用 `spawn_teammate` 工具，终端会打印紫色的 `[Team] 召唤队友 alice 成功`。
2. **异步工作**：老大召唤完就没事了，它会告诉你召唤成功。而后台的 `[alice]` 线程会开始独立工作（调用 `write_file` 写 SQL）。
3. **工作汇报**：几秒钟后，alice 写完了，她会通过 `send_message` 工具把结果发给老大的邮箱。
4. **老大收信**：你什么都不用做，只要稍微等一下，终端就会打印绿色的 `[Inbox] 老大收到 1 条新消息并触发重试`。然后老大就会自动读信，并高兴地向你汇报：“Alice 已经完成了！”

你可以再去看看 `s15_agent_teams/.mailboxes/` 目录，感受一下这种纯粹的“基于文件系统”的多智能体通信方式。
