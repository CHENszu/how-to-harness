# 第六课：Subagent —— 大任务拆小，每个拿到的都是干净上下文

## 核心概念：为什么要召唤子 Agent（小弟）？

设想 Agent 在修一个很深的 Bug。为了找到问题，它可能需要读取 30 个文件，中间思考、尝试运行了 60 个回合。
这个时候，它的上下文里已经塞满了 120 条对话记录，绝大部分是“追踪调用链”的中间过程代码。
**结果就是：它变得非常健忘。它可能完全忘记了最初要修的 Bug 是什么。**

换个角度想：如果你是一个程序员，你在修 Bug 时，可能会“开一个新终端”去测试一下某段代码。测完之后，关掉新终端，把结论写进笔记，然后回到原来的终端继续修主 Bug。

**Agent 也需要这种能力：开一个独立的子进程，给它一个全新的、干净的消息列表，让它专心只做一件事。做完只把结论带回来。**

## 核心改造：新增 `task` 工具

在 s06 中，我们在主 Agent 的工具箱里，加入了一个名为 `task` 的工具。
当主 Agent 觉得任务太复杂时，它就可以调用 `task(description="去查一下这个项目的测试框架是什么")`。

### 1. 干净的上下文 (Fresh Messages)
一旦调用了 `task` 工具，我们的 Python 代码就会启动一个 `spawn_subagent` 函数。
这个函数会**创建一个全新的 `messages = []` 列表**。
子 Agent 不会看到主 Agent 之前那 100 多轮的对话，它只看到一句纯粹的指令：“去查测试框架”。所以它的注意力高度集中。

### 2. 只回传结论 (Summary Only)
子 Agent 在自己独立的循环里，调用 `bash`、`read_file` 去翻找文件，可能折腾了 10 轮才找到结论。
当它结束时，Harness **会把中间这 10 轮的试错过程全部丢弃**。
只把子 Agent 说的最后一句话（“报告老大，测试框架是 pytest”）作为 `task` 工具的返回值，塞回给主 Agent。
这样，主 Agent 的上下文就保持了极度的整洁。

### 3. 禁止无限套娃 (No Recursion)
如果子 Agent 遇到困难，又召唤孙子 Agent，孙子再召唤重孙子……很快就会把 API 的 Token 刷爆，或者陷入死循环。
所以，**子 Agent 的工具箱里，只有 `bash`、`read` 等基础工具，没有 `task` 工具**。它必须亲力亲为，不能再往下甩锅了。

## 核心工作原理：老大与小弟是如何通信的？

在这个主从架构中，老大和小弟的通信**并不是通过网络或者复杂的协议**，而是通过最简单的 **函数调用（Function Calling）的参数与返回值** 来实现的。

### 1. 下行通信：发任务（通过参数）
老大调用 `task` 工具，模型生成 JSON 如下：
```json
{
  "name": "task",
  "arguments": {
    "description": "去读一下 README.md 告诉我它是关于什么的"
  }
}
```
Harness 拦截到请求，执行 `spawn_subagent(description)`。
老大的这句话，变成了小弟 `messages` 列表里的第一条指令。这是老大传话给小弟的唯一途径。

### 2. 隔离干活：小弟的暗箱操作
小弟在自己的 `while` 循环里疯狂调用 `bash`、`read_file` 查资料。
这个过程中产生了几十条对话，全部存在小弟内部局部的 `messages` 变量里。老大在外面**完全看不见**，也不会被这些信息撑爆内存。

### 3. 上行通信：听汇报（通过返回值）
小弟干完活，不再调用工具了，它的循环结束。
此时，Harness 会执行提取操作：
```python
# 提取小弟最后一次说的话
result = extract_text(messages[-1]["content"])
# 作为工具的执行结果，返回给老大
return result  
```
**老大的视角是这样的：**
1. 我调用了 `task` 函数。
2. 我卡在这里等。
3. 一会儿后，函数返回了一句话：“报告，README.md 主要是讲怎么用 todo_write 规划任务的”。
4. 老大把这句话作为工具结果塞进自己的上下文，继续往下思考。

**总结：**这种同步阻塞式的通信，通过一进（参数）一出（返回值），完美切断了上下文污染。小弟干脏活产生的中间垃圾数据，随着函数结束直接被系统回收，老大的大脑依然清爽！

### 第 2 步：体验“甩锅”
你可以输入这样一个 Prompt：
`请派一个小弟（使用 task 工具），去读一下当前目录下的 README.md，然后只告诉我这个项目是关于什么的。`

**观察重点：**
1. 终端里是否打印出了紫色的 `[Subagent spawned]`？
2. 紧接着，你会看到灰色的 `[sub] read_file: ...`，这说明小弟正在自己独立的沙盒里努力干活。
3. 最后打印出 `[Subagent done]`，小弟退场。
4. 主 Agent 收到小弟的结论，然后再用正常的白色字体回答你。

这就是现代多智能体（Multi-Agent）系统最基础的“主从（Manager-Worker）”架构雏形！
